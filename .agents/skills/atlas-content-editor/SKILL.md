# Aphrosyne Atlas 文章编辑

编辑已经存在于本站的 Blog 或 Knowledge .mdx 文章。这个 skill 不导入外部资料，也不因“阅读体验”四个字自动授权大幅改写；导入请求由 atlas-content-import 单独处理。组合请求可以分别执行，但必须把迁移和编辑的范围分开说明。

## 开始前

1. 阅读项目根目录 AGENTS.md，检查 git status，保护用户已有改动。
2. 阅读目标文章完整正文和 frontmatter，确认它是 Blog 还是 Knowledge、稳定 slug 和当前内容格式；只扩展到必要的 schema/校验脚本，不扫描或批量改写其他文章。
3. 判断用户授权的编辑强度。用户只说“优化阅读体验”或“润色”而没有说明范围时，采用保守的轻度校对，或先问一个具体问题确认是否允许结构重组；不要把笼统表述解释成深度编辑。
4. 先记录事实、结论、命令、路径、版本、配置项、引用和作者语气等不可随意改变的内容。

## 编辑强度与授权边界

- 轻度校对：修正错字、明显病句、标点、中文/英文混排和不改变意思的表达问题。尽量保留原句、段落顺序、标题结构、个人语气和信息密度；不主动删减或补写。
- 结构优化：只有用户明确要求时，才调整标题层级、段落拆分、列表/表格/引用的组织、教程步骤、前置条件、警告和结论的呈现。可以改善 Blog 的连续阅读或 Knowledge 的快速查找，但不改变事实、因果关系、作者立场、可复现步骤或稳定 URL。
- 深度编辑：只有用户明确要求重写、重组、删减、压缩、扩写或大幅改写时才执行。开始前先说明预计改动区域、删减/重排原则和可能影响，并在交付时逐项总结重要变化。

用户没有明确授权的强度保持不变。即使获得深度编辑授权，也不能凭空补充实测结果、来源、版本、技术结论或下载地址；不确定内容保留并标为待确认，或询问用户。

## 内容边界

- Blog 可以改善连续阅读，但保留个人经历、判断、语气和叙述视角；不要把它改成 Knowledge 式说明书。
- Knowledge 可以强化可查找性和可复现性：明确前置条件、步骤、警告、版本范围和结论的组织，但不替作者重新验证事实。
- 不修改 slug、稳定 URL、图片归属或外部资料；不负责导入外部文档、迁移图片、整理原图或替换资源。资源确需迁移时停止并交给导入流程。
- 不修改 CSS、颜色、代码块主题、代码高亮、MDX 渲染组件或页面布局。用户要求这些内容时，按普通前端开发任务处理，不由本 skill 接管。
- 默认不改 factual frontmatter（日期、版本、验证状态、来源、发布状态等）；但只要实际修改了 Knowledge 文章内容，就必须同步将 last_edited 更新为本机当前日期，格式为 YYYY-MM-DD。日期必须读取本机系统日期，不得使用来源日期、猜测日期或手写固定日期；如果没有产生实际内容变化，不更新 last_edited。Blog 没有该字段时不要擅自添加。不要自动发布、提交或推送。

## 结构与注释的简洁性

- 目录树、表格和步骤说明优先使用短而明确的注释；不要为了“解释完整”重复正文、标题或相邻节点已经表达过的内容。
- 同一说明适用于相邻多个文件时，标注共同父目录或文件组一次；只有用途不同、容易混淆或需要单独提醒的节点才分别注释。
- 注释放在对应节点旁，使用箭头或明确的路径列连接；不要把说明放在相距很远的位置，让读者猜测它对应哪个文件夹或文件。
- 编辑完成后检查视觉密度：能合并的重复说明合并，不能合并的说明保持最短，不用重复“配置文件”“预设文件”等上下文已经明确的词。

## 技术文章检查

编辑前后逐项对照：命令及其参数、文件/URL 路径、配置项名称、版本号、步骤顺序、前置条件、因果关系、警告、代码块、表格和引用。若文字变化使技术含义、适用范围或复现路径不再与原文一致，撤回该变化或请求用户确认。Markdown/MDX 调整只服务于已授权的文字或结构目标，不借“修格式”之名扩大范围。

## 验证与交付

完成后查看 git diff，确认只有目标文章和用户明确允许的必要文件发生变化，并检查标题层级、代码围栏、列表/表格、行内代码、链接、图片引用和 frontmatter 仍可解析。按改动范围运行项目已有检查：

- 只改文字且未改变 metadata 时，至少运行 npm run verify:content；
- 改动 frontmatter、链接或 Markdown/MDX 结构时，运行 npm run test:content-schema 和 npm run verify:content，必要时更新 npm run generate:content-registry / npm run generate:search-index；
- 影响构建语法或较大范围的编辑，再运行 npm run build。不要用删除内容规避构建错误。

交付时说明：采用的编辑强度与用户授权；保留不变的事实、语气和结构；重要文字/结构变化及其理由；命令、路径、版本、因果关系和引用的核对结果；未解决或待确认项；验证命令与结果。未获授权的导入、图片迁移、样式修改、发布、提交和推送均不执行。
