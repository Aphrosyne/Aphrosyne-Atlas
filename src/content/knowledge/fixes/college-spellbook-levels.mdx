## 症状

角色的召唤达到 60 级、毁灭达到 85 级，但学院商人菲尼斯和法劳达仍只出售低阶法术书。攻击商人后读档、等待多个游戏日均无法改变库存。

## 结论

这不是商人刷新卡住，也不是学院商人箱被错误替换。原版用于控制法术书等级列表的 `PC<学派><档位>` 全局变量（例如 `PCConjurationExpert`）没有随技能升级更新；其值为 `100` 时，对应等级列表的“不出货概率”为 100%，因此该档法术书永远不会生成。

本存档中的直接证据如下：

| 学派 / 档位 | 存档值 | 含义 |
| --- | ---: | --- |
| 召唤 Adept / Expert / Master | 100 / 100 / 100 | 熟练、专家、大师书均被完全排除 |
| 毁灭 Adept / Expert / Master | 0 / 100 / 100 | 熟练书可出；专家、大师书被完全排除 |

这正好解释了“毁灭 85 仍只卖老手级、召唤 60 仍只卖学徒级”的现象。等待只会重新抽取库存，不会把 100% 的不出货概率抽成有货；攻击读档也同理。

## 原版机制与验证过程

1. 先检查学院商人的容器和等级列表链：法劳达的商人箱为 `00098BA1`，菲尼斯为 `00098BA2`。其中的法术书等级列表保留完整，没有被 `DynamicContainerLoot.esp` 删除或替换；该插件只追加了战利品。
2. 检查 50 / 75 档法术书等级列表：列表的 `LVLG` 分别指向该学派的 `Adept` / `Expert` 全局变量。`LVLG` 的值用作 chance none：`0` 表示会生成，`100` 表示绝不生成。
3. 解析最新存档的全局变量表，读取到上表数值。AE 1.6.1170 存档为 LZ4 压缩；解析器按 File Location Table、GlobalData 表和 3 字节 RefID 规则解析，而不是在压缩文件里直接搜 FormID。
4. 检查原版任务 `WISkillIncrease02`（`000F2593`）及其脚本属性：它引用全部 18 个 `PC*` 技能阈值全局，原本应在技能提高时更新它们。
5. 扫描加载插件后，没有发现其他插件覆写这些原版 GLOB 记录；商人容器最终覆盖也未改变法术书列表的 `LVLG` 链。

因此可确认“全局状态未更新”，但不能仅凭本次数据指认某一个具体 mod：任何绕过原版技能提升故事事件、直接设定技能等级或改变升级路径的机制，都可能让 `WISkillIncrease02` 未及时同步。整合包中涉及技能升级的 mod 较多，逐个删除会破坏玩法且收益不高。

## 修复边界

整合包侧已采用定时脚本同步这组全局变量。这是针对大量兼容来源的合适修复：按当前技能等级把相应 `PC<学派>Adept/Expert/Master` 设为允许出货的值，再等商人正常重置库存即可。

曾尝试的 `SetGlobalValue ...` 不是游戏控制台命令；不要把它用于控制台。若需要手动救急，应优先使用整合包提供的兼容脚本或在备份存档后用 ReSaver 编辑 Global Variables，而不是反复攻击、读档或盲目重置任务。

## 可复用检查方法

- 解析 AE 1.6.1170 LZ4 存档，检查 File Location Table、全局变量及 18 个技能阈值全局。
- 检查 `WISkillIncrease02` 和玩家的 ChangeForm。
- 定向查找存档中 `WISkillIncrease02` Papyrus 实例。
- 输出 CONT、LVLI、GLOB 的直接记录和 `LVLG` 关联。
- 扫描技能相关记录在加载顺序中的最终覆盖来源。

## 相邻但不同的问题：学院法袍

学院商人出售的原版学派法袍不受上述 `PC*` 全局和技能等级控制，而是按玩家**角色等级**的等级列表（1 / 8 / 16 / 24 / 32）决定。角色 18 级时最高自然出现第 3 档；24、32 级后才会有更高档。该链没有 `LVLG` 全局变量。
