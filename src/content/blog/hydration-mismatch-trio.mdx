给 Dashboard 加了时钟、音乐播放器、FFT 波形、Steam 游戏卡片四个组件，结果连续触发三次 `Hydration failed` 错误。记录一下这三个坑。

## 第一个：`new Date()`

时钟组件用 `useState(() => new Date())` 初始化——`useState` 的函数参数在 SSR 和客户端各执行一次，产生不同的时间戳。

```tsx
// ❌ SSR 渲染 14:32:05，客户端 hydrate 时已经是 14:32:06
const [now, setNow] = useState(() => new Date())
```

解法：初始值设 `null`，SSR 和客户端都渲染占位符，`useEffect` 里才设真实时间。

```tsx
const [now, setNow] = useState<Date | null>(null)
useEffect(() => {
  setNow(new Date())
  const id = setInterval(() => setNow(new Date()), 1000)
  return () => clearInterval(id)
}, [])
// SSR 和客户端都渲染 "--:--:--"，hydrate 后才变真实时间
```

## 第二个：`Math.random()`

FFT 波形组件用 `useState(() => generatePlaceholderHeights())` 生成随机占位高度。和 `Date` 一样，`useState` 的初始化函数在 SSR 和客户端各跑一次，`Math.random()` 产生不同的数组。

```tsx
// ❌ SSR 和客户端的随机数不同
const [placeholder] = useState(() => generatePlaceholderHeights())
```

解法：初始值用固定数组，`useEffect` 里再生成随机值。

```tsx
const [placeholder, setPlaceholder] = useState(() => new Array(32).fill(0.3))
useEffect(() => {
  setPlaceholder(generatePlaceholderHeights())
}, [])
```

## 第三个：`disabled={null}` vs `disabled={true}`

音乐播放器的按钮用 `disabled={!ready}` 控制状态。`ready` 初始 `false`，所以 `!ready` = `true`，两边应该一致。但错误信息显示一边是 `disabled={true}`，另一边是 `disabled={null}`。

```tsx
// ❌ React 把 null 和 undefined 当作「移除属性」，和 true 不匹配
<button disabled={!ready}>...</button>
```

这个最诡异——`ready` 初始值在 SSR 和客户端都是 `false`，理论上不该有差异。可能是 React 19 对 `disabled` 属性的序列化逻辑有边界情况，也可能是 dev server 编译缓存的问题。清了 `.next` 缓存也没用。

解法：不用 `disabled` 属性，改用 CSS class 控制交互。

```tsx
// ✅ 没有 HTML 属性差异，纯 CSS 控制
<button className={`${ready ? 'hover:bg-white/20' : 'opacity-30 pointer-events-none'}`}>
```

## 第四个：`useRef(Math.random()).current`

后来在 Playground 缩略图里又踩了一次：为了让组件零重渲染，用 `useRef(Math.random()).current` 取一个随机种子。自认为 `useRef` 只初始化一次，两边一样——错了。

```tsx
// ❌ SSR 和客户端各跑一次 Math.random()，值不同
const variant = useRef(Math.random()).current
// SSR 渲染 <svg>（particles），客户端渲染 <div>（cube）→ mismatch
```

`useRef` 的初始化参数只在 mount 时执行，但 SSR 和客户端分别 mount，所以 `Math.random()` 仍然跑两次。

解法：和 `useState` 一样，初始值固定，`useEffect` 延迟设值。

```tsx
// ✅ SSR 固定渲染 cube，客户端 mount 后再随机
const [variant, setVariant] = useState(0)
useEffect(() => { setVariant(Math.random()) }, [])
```

## 教训

1. **`useState` 的初始化函数不是纯客户端的**——SSR 时也会执行。凡是有副作用的（时间、随机数、`window`），一律用 `null` 初始 + `useEffect` 延迟。
2. **`useRef(Math.random()).current` 也不行**——SSR 和客户端分别 mount，`useRef` 初始化各跑一次，值不同。
3. **`disabled={null}` 在 React 里等于移除属性**，和 `disabled={true}` 不同。如果 SSR 和客户端对同一个条件判断的值不一致，就会 hydration mismatch。最安全的做法是用 CSS class 替代 HTML boolean attribute。
4. **Dev server 的编译缓存可能让你以为修了但没修**。改完代码还报错，先 `rm -rf .next` 再试。
