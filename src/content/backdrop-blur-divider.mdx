Dashboard 用 CSS Grid 布局，卡片之间有 `gap-4` 的间距。大部分卡片看起来正常，但一言（Hitokoto）卡片的上方总有一条隐约的分隔线——像是阴影，又像是边框。

## 现象

一言卡片位于第 6 行，横跨 7 列。它上方是 Playground 卡片（col 1-3）和 Contributions 卡片（col 4-7），中间有一条 grid gap。那条分隔线就出现在 gap 对应的位置，横贯一言卡片顶部。

一开始以为是卡片的 `box-shadow` 泄漏到了 gap 里。把默认阴影去掉了，还在。

以为是 `border-t-white/20` 的上边框。不是。

以为是 `overflow-hidden` 没生效。加了 `!important`，也没用。

## 原因

最后把一言卡片的 `backdrop-blur-[15px]` 去掉——分隔线消失了。

`backdrop-blur` 会对元素背后的内容做高斯模糊。当卡片紧邻一个 gap（透明区域）时，模糊算法会把 gap 的透明像素和卡片边缘的像素混合，在边界处产生一条可见的过渡带。这条过渡带看起来就像一条阴影分隔线。

其他卡片没这个问题，是因为它们上方要么没有 gap，要么 gap 很小不容易察觉。一言卡片横跨两列，上方恰好有两个卡片之间的 gap，过渡带被拉到了整行宽度，非常显眼。

## 解决方案

最初给一言卡片加了 `!backdrop-blur-none` 来强制去掉模糊，分隔线消失了。

```tsx
<Card direction="left" className={`${GRID.hitokoto} !backdrop-blur-none`}>
  <HitokotoCard />
</Card>
```

但后来在解决第二个问题（见下文）时，重新调整了卡片顺序和飞入方向。调整后即使去掉 `!backdrop-blur-none`，分隔线也不再出现。说明 `backdrop-blur` 的视觉伪影和卡片在 DOM 中的上下文有关——不同的相邻元素、不同的飞入方向会影响模糊算法在边界处的混合结果。

## 小结

`backdrop-blur` 在以下场景可能产生视觉伪影：

- 元素紧邻透明/半透明的 gap 区域
- 元素背后有高对比度的边界
- 伪影的出现和 DOM 顺序、动画方向有关，不一定稳定复现

遇到类似的「莫名阴影/分隔线」问题，可以优先排查 `backdrop-blur`，但不必急着加 hack——先试试调整元素顺序或动画方向。

## 第二个问题：底部卡片用 `bottom` 方向飞入会卡滚动

解决了分隔线之后，又遇到了一个更诡异的问题：Dashboard 卡片的入场动画会导致首次滚动卡顿。

### 现象

刷新页面后，第一次向下滚动时鼠标滚轮只能动一点点，然后就卡住了。之后再滚就正常了。

### 排查

用穷举法测试：

- 把一言卡片（最后一行）的飞入方向从 `bottom` 改成 `left`——不卡了。
- 把播放器挪到最后一行，飞入方向用 `top`——不卡。然后把方向改成 `bottom`——卡了。
- 把时钟挪到最后一行，飞入方向用 `top`——不卡。改成 `bottom`——卡了。

结论：**位于 grid 最底部的卡片，不能用 `direction="bottom"` 飞入**。

### 原因

Framer Motion 的 `whileInView` 会在元素进入视口时触发动画。当卡片在页面最底部且用 `bottom` 方向飞入时，动画从 `y: 80`（向下偏移）过渡到 `y: 0`。在动画开始的瞬间，卡片向下偏移 80px 导致页面高度增加，浏览器需要重新计算滚动区域。这个重计算触发了滚动事件，而滚动事件又触发了 `whileInView` 的重新检测，形成一个短暂的反馈循环，表现为首次滚动卡顿。

其他方向不会触发这个问题，因为 `x` 方向的偏移不影响页面高度，`top` 方向的偏移是向上（不会增加页面底部高度）。

### 解决方案

最底部的卡片避免使用 `direction="bottom"`，改用 `left`、`right` 或 `top`。
