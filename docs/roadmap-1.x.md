## 使用约定

- `[ ]`：待处理。
- `[~]`：正在实现或等待验收。
- `[x]`：已完成并验收。
- `[-]`：决定不做，保留原因。

每个问题尽量附上页面、现象、复现条件与验收标准。不要在本文件记录 Token、本机绝对路径、私人链接或未确认可公开的素材来源。

## 收集箱

### 界面与交互

- [ ] [UI][P1] 继续研究首页 Profile 卡片的 backdrop-filter 模糊带。
  - 页面：首页 Dashboard。
  - 现象：滚动或悬停 Knowledge 条目后，Profile 区域曾出现位置不固定、数量不固定的模糊条带。
  - 当前状态：已将 Profile 与 Knowledge 卡片改为无 backdrop blur，等待长期使用中的视觉验收与后续独立研究。
  - 验收：桌面与移动端滚动、悬停和主题切换下均不出现条带；形成可复现结论后更新对应 Blog 记录。

- [ ] [UI][P2] 讨论首页 Hero 文案、署名和诗句的长期表达方式。
  - 页面：首页 Hero。
  - 当前状态：已移除“在下”，其余文案暂不改动。
  - 验收：文案与站点的个人主页、内容档案和 Skyrim 知识库定位一致。

- [x] [UI][P3] 尝试美化一下整体布局风格等
  - 目前来讲，可能不想一个博客，在考虑，不同页面使用不同背景，而不是和hero页一致
  - 知识库、博客、项目页左上角的文字白色，与背景颜色接近有点不方便看，考虑如何改动
  - 结论：首页保留 Hero 插画；内容页改用按板块区分的主题渐变背景，标题与摘要改为主题前景色。细节见 `docs/ui-refresh-1.x.md`。

- [x] [UI][P4] 美化手机布局
  - 当前在手机端看起来比较拥挤，图标或者导航栏形状也不美观
  - 结论：小屏页头改为 Avatar、菜单、搜索三个独立入口；Knowledge 分类改为两列触控网格，避免横向截断。


### 内容迁移

- [ ] [Content][P1] 按内容价值逐篇迁移后续文章，并选择 Blog 或 Knowledge 的合适归属。
  - 验收：每篇公开内容具有可解析元数据、稳定 URL、来源/授权说明与必要的图片资源。

### 技术债与质量

- [ ] [Quality][P1] 对 1.0.0 执行独立 code review，并建立修复批次。
  - 范围：静态导出路径、前端渲染边界、内容加载器、Dashboard 客户端请求与公开资源。

- [ ] [Quality][P2] 清理 React 19 ESLint 基线。
  - 当前基线：`npm run lint` 为 25 errors、5 warnings；`npm run build` 通过。
  - 验收：先区分规则升级带来的误报与真实问题，再逐项消除，不通过关闭规则隐藏问题。

- [ ] [Architecture][P3] 为 Blog 元数据解析替换 `new Function`，并补充覆盖中文、CRLF 和异常 frontmatter 的测试。

- [x] [Architecture][P2] 将已追踪的原始图片与完整字体迁移为发布产物，并单独瘦身 Git 历史。
  - 范围：头像与 Knowledge 的现有图片源文件、`public/images/` 下遗留的直接原图、已从工作树删除但仍在历史中的 `assets/images-source/bg/bg.jpg`、`src/app/fonts/` 下的三份完整 OTF；背景图已先行采用“本地原图、提交 WebP”的模式。
  - 约束：图片原图和字体源均保留本地备份；先备份仓库并在独立分支验证，再使用专用历史改写工具。改写后需要协调 force-push 与所有克隆仓库重新同步。
  - 实现方向：提交发布 WebP 和已生成 WOFF2，调整构建脚本使缺少本地原图／OTF 的干净 checkout 仍可直接构建；需要重新压缩时由本地作者工具显式执行。
  - 验收：干净 checkout 仅凭提交的发布资源即可通过 `npm run build` 并部署；仓库当前与历史中的原图、完整字体体积均已按计划处理。
