# Aphrosyne Atlas UI/UX 审阅与优化规划 · 2026-09

审阅日期：2026-09-14。审阅对象：当前工作树实际运行结果。性质：审阅与规划，未实施界面改动。

## 1. 审阅范围与实际测试环境

### 1.1 结论摘要

Aphrosyne Atlas 已经具有明确的个人视觉身份，也已完成一部分有效的共享样式建设。优先级最高的工作是修复手机阅读容器和 About 的横向溢出、补齐搜索弹窗的焦点管理、建立可读的主题语义色，然后整理路由和页面内部动效的职责。无需重做首页，也无需把它改成文档模板。

最重要的五组发现：

1. **手机阅读被实际截断**：390px 视口中，MDX 测试帖的文档宽度达到 970px，Experience 知识条目达到 720px，About 达到 768px；深浅主题均不能解决布局根因。
2. **主题变量存在，但组件没有完整遵循语义角色**：知识状态浅色文字、首页的白色装饰文字与深色链接、About 白色技能标签、浅色模式下深色代码块的行号均有可读性问题。
3. **搜索可用，但不是完整的可访问模态框**：中文检索和结果跳转成功；键盘焦点可以进入背景页面，缺少对话框语义、输入标签、手机关闭按钮和焦点归还。
4. **路由动效尚未形成完整系统**：持久背景已经有切换逻辑，但正文分别采用无动画、仅标题淡入、整张玻璃面板淡入、卡片位移等方式；现有 `PageTransition` 没有退出阶段。手机菜单还会直接推动正文。
5. **长文的稳定性和定位能力需要专门一轮优化**：懒加载图片没有尺寸预留；手机和平板隐藏了文章目录；知识侧栏长标题普遍截断。正文基本字号和桌面行宽反而已有可保留的基础。

### 1.4 证据方法与限制

- **V**：真实浏览器截图、交互及只读 DOM 测量；**C**：当前代码事实；**R**：由事实推导的风险；**S**：主观方向。下文明确区分它们。
- 实际检查了导航点击前、点击后的等待/切换阶段和稳定页面；冷路由编译时能看到旧内容暂留。CUA 的截图采样不是连续逐帧录屏，无法以此证明 380ms 动画每一帧均无闪烁。退出阶段是否存在，另以组件实现核对。
- 浏览器读取到的当前开发站 error/warn 日志为空，未观察到 hydration、未处理运行时异常或文章图片加载错误。这不是全站零错误保证。之前开发日志里的跨来源 HMR 警告不属于本轮 localhost 点击产生的问题。
- 没有生产性能 trace、真实 CLS/INP/LCP 数值、CPU/GPU 时间、网络限速、禁用缓存或真机软键盘测试。下文性能项均标为风险或待量测，不伪造性能成绩。
- 当前浏览器能力仅提供视口/可见性控制，没有 reduced-motion 媒体模拟；本会话原生系统设置控制不可用。因此 reduced-motion 做了实现审计，**没有完成 reduce=true 的运行验证**。
- 404 已实际触发；运行时 `error.tsx`、搜索索引请求失败、背景请求失败没有注入故障，只有代码检查。Studio 的拖拽、剪贴板和下载未测，已验证不依赖拖拽的选择/尺寸按钮。
- 用户截图已逐张观察。截图用于视觉参照；工具截图未另存进项目，本文 V 编号是测试记录，不是假称已有截图附件文件。

### 1.5 Skill 与版本依据

已使用 `ui-ux-pro-max` skill，先运行与 `personal blog Skyrim knowledge glassmorphism dark light theme Chinese reading` 相关的 `--design-system` 参考生成，再分别检索 animation、layout shift、responsive、Chinese reading typography、glassmorphism dark/light color、accessibility/keyboard/reduced-motion，以及 `--stack nextjs` 规则。

## 3. 做得好的部分：应明确保留

1. **首页全屏 Hero 与诗句、姓名的个人表达。** 不缩成普通标题区；手机也保留整屏氛围。调整应围绕可读性、裁切焦点、入口语义与滚动锚点。
2. **持久背景与 Navbar。** Root layout 已将背景、导航和 Footer 放在页面之外；跨页没有必要重新创建整套外壳。
3. **Blog / Knowledge / Projects 的共享列表卡片基线。** `content-card.ts` 已集中圆角、边框、透明度、padding、hover、focus 样式，避免重新发明一次“统一卡片”。
4. **稳定的排序分段控件。** Blog 实测升降序切换前后均为 254×52px，位置一致；源码已有固定分段空间。
5. **已经预留滚动条槽。** `html { scrollbar-gutter: stable; }` 存在；桌面样本 Navbar 没有因长短页切换出现典型滚动条横跳。后续不要把“加 scrollbar-gutter”当作新的根因修复。
6. **两类内容采用不同信息架构。** Blog 的日期/标签适合记录；Knowledge 的类型、版本、验证状态、来源与目录适合长期查阅。应共享阅读能力，保留这些差异。
7. **本地中文字体、静态资源路径处理、核心中文搜索。** 无需换字库、搜索后端或新增依赖来完成视觉系统工作。
8. **背景快速切换的防过期回调逻辑和 reduced-motion 分支。** `transitionId` 可以避免旧动画完成回调恢复错误背景；这些已有防护应保留。
9. **目录可操作性已有投入。** 桌面 sticky 目录、可访问滚动条属性与键盘处理是可延续基础；不是从零换目录插件。

| 菜单推动正文 | 手机 Projects：header60→566px；h1 y124→630 | 已确认506px布局推动；菜单改为独立浮层或抽屉，并处理焦点/滚动 |

| 图片加载 | 长教程未加载图片无width/height，框可为0×0；加载后首图734×412.875 | 已证实没有尺寸预留；属于高度插入风险，不宣称已测到CLS数值 |

| 客户端动态内容 | Clock/状态/一言更新；首页玻璃卡片保留区域 | 本轮没有运行时错误；不同长度的一言/状态仍应做高度与换行压力测试 |
| 同板块列表→详情 | Projects背景保持同一人物图；内容换成窄详情卡 | 稳定背景是正确行为；正文没有完整退出段 |
| 跨板块切换 | Blog/Knowledge/Projects/About各自图片发生替换与滑入 | 保留品牌方向；冷图片无decode门控，旧新面板承接仍需帧级验证 |
| 直接刷新/历史 | 当前开发站深层刷新成功；项目后退/前进正确 | 尚未覆盖全部哈希+长文+筛选历史组合；静态3000异常另记 |
| 旧新内容叠加/空白 | 当前源码样本未见持久叠页或持续空白；冷编译时旧页等待 | 不将开发等待时间当成生产动效时长；不声称所有帧均已验收 |

布局量测不等同于 Web Vitals：有用户操作后的页面高度变化并不必然计入 CLS，但仍可能造成明显 UX 跳变。验收应同时记录感知稳定性和浏览器指标。

## 6. 页面动画审计与 Motion System 建议

### 6.1 当前职责缺口

- `src/components/shared/PageTransition.tsx` 仅 `opacity:0→1`、400ms、easeOut；没有 `exit`，也没有路由层退出保留机制。组件名称不代表它完成了完整路由过渡。
- Blog/Knowledge 详情没有统一 route motion；列表标题、卡片和 Projects/ About 又分别入场，节奏不同。
- 背景本身较完善：旧图底层、新图±6%滑入、scale1.08、380ms、`[0.22,1,0.36,1]`；同板块不必重播。首页/About 还以整页 scrollProgress 关联0–12px blur。
- Dashboard 约500ms、多向80/120px位移、60ms stagger，和阅读页短淡入是不同强度；可以保留首页的特别表现，但需要总延迟预算和手机降级。
- 对带 backdrop-filter 的整层 opacity 动画仍然存在。当前截图没有证明持续的模糊带故障，但源码与项目既有排查记录足以要求针对合成边界验证，不能直接套用 `transform-gpu`。

### 6.2 三层职责与建议参数

下表是待实施候选 token，不是本轮改动。先在现有 Framer Motion/CSS 内实现，不引入新动画依赖。

| 层级 | 包含内容 | 建议节奏 | 属性与约束 |
| --- | --- | --- | --- |
| 持久层 | Root背景承托、Navbar、Footer布局轨、全局主题 | Navbar不跟正文退场；主题颜色160–240ms；背景保留现有380ms为基线 | 不对根布局/整页高度做动画；背景变换与文字入场独立；同板块不重播 |
| 路由层 | 列表内容区、阅读内容区、名片主体 | exit100–140ms；enter180–240ms；完成替换的视觉阶段目标≤380ms，不含真实加载 | 内容translateY 6–12px或opacity；玻璃底板保持稳定，优先动画其内部文字层；不要叠加两次淡入 |
| 内部入场 | 列表首屏卡片、Dashboard表达卡片 | 普通列表200–260ms，stagger24–40ms，总额外延迟≤160ms | 普通页位移8–16px；只首屏有限项错峰，不能第30项等数秒 |
| 微交互 | 按钮、标签、卡片hover/focus、目录高亮 | 120–180ms；弹窗180–220ms | transform/opacity适合小位移；颜色单独transition；hover位移≤2px，点击缩放0.98–1 |
| 首页特例 | Hero箭头、头像光环、Dashboard首入 | 可保留较丰富方向；桌面卡片建议先试24–48px、320–420ms | 不缩减Hero高度；平板/手机减少卡片长距离飞入；避免页面底部从很远处飞入造成滚动抖动 |

Easing 建议集中为：enter `cubic-bezier(0.22,1,0.36,1)`、exit `cubic-bezier(0.4,0,1,1)`、micro `cubic-bezier(0.2,0,0,1)`。普通内容不使用明显回弹；可保留头像、Meme等表达性组件的独立曲线。

### 6.3 完整退出与 Next.js 的实施边界

当前版本文档明确：共享 layout 在导航间保留；template 会在对应 segment 的 key 变化时重新挂载子树；query 变化本身不会按同一方式重挂载。**template 的重挂载不是退出动画机制**，根 template 也不能被假定为所有深层文章 slug 变化都产生完整生命周期。

建议后续 Motion Pass 先做一个范围受控的验证闭环：Blog 列表→文章→另一文章→Knowledge→后退。必须验证鼠标链接、键盘链接、浏览器历史、哈希和快速连续导航。若选用 Framer Motion，应先证明路由协调层能在替换前保留可退出的旧视觉内容，并让新内容和滚动恢复在正确时机接管；不能仅用 `AnimatePresence key={pathname}` 就宣布 App Router 退出已完成，不使用私有 router context 冻结技巧。

当前 Next 的 View Transition 支持仍含实验性配置。可作为 **Optional Exploration 的隔离验证选项**，不作为本站静态维护的默认前提；尤其带玻璃的快照、固定背景、长文高度差需要实测。不能为了动画把静态内容改成依赖常驻服务端的页面。

完整系统的安全退路应是保留当前内容直至新内容可显示，并完成轻量进入/状态反馈；如果退出协调尚未验证，就把“完整退出”标记为未完成，不能用空白停顿或强制所有链接延迟伪装退出。

### 6.4 防止塌陷、闪烁与滚动异常

- 不把旧新页面同时放进普通文档流累加高度；如退出阶段临时叠层，旧层只作非交互视觉承托，新层接管正常流。临时测量承托需及时释放，不能固定所有页面高度。
- 玻璃底板和内容 motion 分层；避免对整张 backdrop-filter 面板同时动画 opacity、filter和scale，不对 blur 使用 `transition-all`。
- 先等待目标背景资源可绘制，再开始背景过渡；保留旧图或主题底色失败降级。只预热合理数量的相邻板块，不一次加载所有正文图片。
- 当前按整页高度控制 Home/About blur，会让内容高度变化影响模糊速度；可探索以Hero离开距离或固定滚动区间驱动，保持背景语言但稳定节奏。
- 新路由、返回列表、历史恢复和hash锚点分别定义滚动政策；尊重浏览器历史恢复，不在每次pathname变化时无条件smooth滚到0。
- 使用统一的 `scroll-padding-top` / 内容锚点 `scroll-margin-top`，目标在导航下方留12–24px；Hero“进入内容”同样适用。
- 不为等待编译/网络扩大动画时长；若提供等待反馈，放在触发控件的稳定区域，避免所有静态页面强行先显示骨架。

### 6.5 手机与 reduced-motion

手机普通路由位移减至4–8px，卡片stagger≤24ms，尽量不让整屏背景横移。减弱动画时取消空间飞入、背景滑动、连续旋转和自动跑马灯的运动，保留必要的即时状态变化或≤100ms淡变；用户触发滚动采用即时或符合系统偏好的行为。内容、目录、标签和技能清单必须完整可读，不能只是暂停在被裁掉的中间帧。

此处减少的是特定模式下的运动刺激，不是删除本站的默认动画，也不是用关闭全部动画掩盖布局问题。

### 7.2 可量化项与不能假装量化的项

- 纯色白字 `#fff` 对当前深色 accent `#3b9a9a` 的相对亮度对比约 **3.35:1**；小字号选中标签/按钮白字不足4.5:1。浅色 accent 白字约 **7.07:1**。应区分 accent装饰色和承载白字的accent-fill，不必改变品牌主色。
- 浅色模式行号 `#6b6b6b` 对实测github-dark代码背景 `#24292e` 约 **2.75:1**；用独立代码行号色解决，不影响正文主题。
- 知识“已验证”实测在浅玻璃面上是很淡的绿色；状态类直接用 `text-emerald-300`，缺少light专用前景，而Projects已区分light/dark。此问题有视觉和代码证据，但未对每个背景像素计算准确比值。
- 首页、About、404、空结果的透明文字与图片混合，不能只拿CSS fg/bg做一个比值宣布通过。验收需要在明亮、阴暗、模糊后和不同构图下检查最终承托区域。

### 7.3 玻璃层级建议

建立三类命名表面即可：**表达玻璃**（Hero后Dashboard，最轻透）、**内容玻璃**（列表、工具栏）、**阅读玻璃**（长文，更稳定的局部承托）。弹窗另有overlay与高不透明度表面。保留背景可见和玻璃边缘，不把所有卡片变成实色，也不让正文为了“透明感”失去持续可读性。

统一表面色/透明度、边框强度、blur和阴影的组合，而不是只统一一个圆角。hover时不要同时显著改变透明度、阴影、位移和字色；明确主反馈，focus采用清楚的轮廓。

## 10. 可访问性与 reduced-motion

当前已有部分focus-visible ring、44px移动导航与分类按钮、目录键盘控制、背景减弱动画分支。但完整键盘流程还有实质缺口。

- `html lang="en"` 与中文主体不符，应为合适的中文语言标记；首页姓名目前不是语义H1，Hero下箭头缺少可访问名称。
- 搜索没有dialog/aria-modal，输入仅placeholder；实际Tab能到背景“搜索文章”输入框。需让背景不可交互、循环焦点、Escape及可点击关闭、关闭后回触发按钮；结果数量/失败状态应可感知。
- 桌面下拉由mouse enter/leave驱动；链接虽有expanded状态，但没有等价的键盘展开控制。768px触屏落在桌面导航断点，尤其需要触摸路径。可采用“板块链接＋独立展开按钮”，不让第一次点击含义模糊。
- 当前页面/分类/标签的视觉选中应补对应`aria-current`或`aria-pressed`等合适语义；排序控件已提供可访问状态，不需统一成无语义div。
- BackToTop隐藏时仅opacity与pointer-events变化，仍可能进入Tab序列；恢复滚动位置时初始可见性也需同步。减弱动画时不应强制smooth滚动。
- About跑马灯整个重复轨`aria-hidden`，没有单份技能语义列表。现有reduce CSS只暂停动画，不能保证被裁掉的技能仍能读到。应给辅助技术保留一份清单，reduce模式用可换行静态布局。
- Hero循环、Dashboard入场、词云旋转、PageTransition、搜索动效和BackToTop没有完整统一的reduced-motion策略；不能因为Backdrop已处理就宣布全站通过。
- 页面嵌套`main`应收敛为一个主内容地标；正文链接需要常驻非hover线索。必要按钮以44px为本站触控目标，密集桌面控件另按实际间距核验。

以上是浏览器/代码审计，不是完整屏幕阅读器兼容性认证。真机VoiceOver/TalkBack、Windows高对比度和200%缩放仍列入后续验收。

## 11. 按页面/组件列出的开发问题单

优先级：P0=核心站点不可用或严重阻断；P1=核心阅读/操作/可访问性明显受损；P2=一致性、效率或稳定性风险；P3=可选审美与精修。本轮没有证据支持全站P0。工作量“小/中/大”为相对范围估计，不是工期承诺。

### A01 · 阅读页与 About 横向溢出

- **分类 / 页面 / 视口主题：**客观缺陷；V04/V06/V10；390浅、Knowledge390深，About768浅。
- **现象与证据：**全文宽970/720/768px，正文与头像被推出屏幕；见第9节测量。C：Blog/Knowledge的`[slug]/page.tsx`、`AboutContent.tsx`、root flex布局。
- **可能根因：**外壳缺少明确可收缩宽度，内部min-content经表格/代码/长标题/跑马灯传播；需实改定位验证。
- **推荐改法：**逐层约束w-full/max-width/min-width，表格与pre局部滚动，检查上下篇flex项、窄屏grid与跑马灯容器。不能全局隐藏overflow掩盖。
- **品牌影响：**无；保留玻璃、字号和Hero。**优先级 / 工作量：P1 / 中。**
- **风险依赖：**修复后行数与页面高度会变，需重验TOC、锚点、Footer和文章间切换。
- **验收：**三篇样本在390和768深浅主题document不宽于布局可用区域超过1px；所有文字可读；仅代码/表格可内部横滚。

### A02 · 手机导航展开造成大幅布局推动

- **分类 / 范围：**客观交互问题；Navbar；390浅，V08/V14。
- **现象与证据：**header由60增到566px，Projects标题从y124移到630；C：移动导航在header正常流内。
- **根因 / 改法：**将菜单容器与页面流分离，使用受视口高度约束的浮层或抽屉；保留全部板块和子入口，补Escape、焦点与关闭后恢复。
- **品牌影响：**低，延续玻璃菜单。**优先级 / 工作量：P1 / 中。**
- **风险依赖：**小屏横屏、菜单内部滚动、背景滚动锁、导航后焦点。
- **验收：**打开/关闭菜单不改变正文几何位置；390×844与横屏均能访问全部项；键盘不会落到被盖住页面。

### A03 · 搜索弹窗焦点与语义不完整

- **分类 / 范围：**可访问性问题；SearchModal；1440/390浅，V11。
- **现象与证据：**Tab连续移动可聚焦背景Blog输入；AX无dialog、输入无名称；手机无明确关闭按钮。C：`SearchModal.tsx`。

- **品牌影响：**无，保留现有居中玻璃弹窗。**优先级 / 工作量：P1 / 中。**
- **风险依赖：**嵌在sticky Navbar的层叠上下文、移动键盘可视区域、路由跳转后焦点目标。
- **验收：**Tab/Shift+Tab闭环、Escape关闭、焦点回搜索按钮；结果打开文章后主标题可感知；背景不可操作。

### A04 · 搜索状态与结果辨识不足

- **分类 / 范围：**一致性/可访问性及失败降级风险；SearchModal；桌面手机浅，V11/C。
- **现象与证据：**中文搜索可用；长标题在一行内截断，桌面右侧URL也截断；有空结果文字但无请求失败UI。fetch未处理catch；没有展示已有excerpt。
- **根因 / 改法：**结果用两行标题＋内容类型/简短摘要；建立加载、无结果、请求失败/重试状态，控制max-height与内部滚动，不增加搜索后端。
- **品牌影响：**低。**优先级 / 工作量：P2 / 中。**
- **风险依赖：**索引体积和现有8条限制；请求失败本轮未强制模拟。
- **验收：**同关键词多结果可区分，空/失败不同文案；手机软键盘出现时仍能关闭和选结果；请求失败不出现未处理异常。

### A05 · 浅色语义标签与强调底色对比

- **分类 / 范围：**可访问性；Knowledge状态、全站accent白字；V05/V06/V12。
- **现象与证据：**浅色“已验证”文字很淡；状态用固定emerald300等；深色accent白字纯色计算3.35:1。
- **根因 / 改法：**统一status前景/背景/边框的双主题token；分离accent、accent-fill、on-accent，参考Projects已存在的明暗状态写法。
- **品牌影响：**无须改主色，低。**优先级 / 工作量：P1 / 小至中。**
- **风险依赖：**半透明面板必须按最终混合效果复核，不能只验token表。
- **验收：**普通标签文字≥4.5:1，语义不只靠颜色；深浅均可辨识verified/needs-review/outdated。

### A06 · 首页卡片浅色可读性与平板密度

- **分类 / 范围：**可访问性/响应式一致性；Dashboard；1440深、768/390浅，V01。
- **现象与证据：**白色低alpha区块名、深色“查看全部”、小日期压在同一复杂背景；768 Projects子卡片标题缩成“Ap…”等。C：Dashboard轻玻璃、微小字号及桌面Grid分配。

- **风险依赖：**卡片布局配置集中管理；不能破坏现有GRID/DIR和内容滚动范围。
- **验收：**768可辨认三个项目名称；必要文字在亮/暗背景均可读；手机无嵌套滚动误触导致的主要入口不可达。

### A07 · Hero 内容入口被导航遮挡、缺少名称

- **分类 / 范围：**客观/可访问性；Hero→Dashboard；1440深，V01/C。
- **现象与证据：**下箭头跳到Dashboard顶端0附近，sticky Navbar覆盖卡片顶部；按钮约28px且无可访问名。

- **品牌影响：**无，不缩小Hero。**优先级 / 工作量：P2 / 小。**
- **风险依赖：**导航高度token、reduced-motion滚动行为。
- **验收：**鼠标/键盘进入内容后首个区块完整位于Navbar下；按钮可被辅助技术识别。

### A08 · 页间动效缺少真实退出与统一节奏

- **风险依赖：**Next16 App Router、历史恢复、静态导出；实验API不作为默认依赖。
- **验收：**跨板块、同板块文章互跳、前进后退均有可解释承接；无空白等待/叠页/提前消失；退出是否完成有录屏证据。

### A09 · 玻璃合成与背景加载门控

- **分类 / 范围：**性能/视觉稳定性风险；Backdrop、About、Projects详情、Knowledge列表；C及V。
- **现象与证据：**带blur整层opacity与多处blur层并存；背景切换没有等待decode；本轮未复现截图文章中描述的Profile模糊条纹。
- **根因 / 改法：**稳定玻璃底板与内容动效分层，背景完成资源准备后滑入；定位合成边界，禁止通用transform-gpu补丁。
- **品牌影响：**低，玻璃保留。**优先级 / 工作量：P2 / 中。**
- **风险依赖：**GPU/浏览器差异与冷缓存，必须实际trace，不能仅数blur数量下结论。
- **验收：**冷/暖缓存和快速连续导航无背景白闪、模糊延迟突现；低功耗设备滚动无可复现周期卡顿。

### A10 · 长教程图片无尺寸预留

- **分类 / 范围：**布局稳定性/性能风险；Boss教程；1440浅，V07。

- **品牌影响：**无。**优先级 / 工作量：P1 / 中。**
- **风险依赖：**需核对原始资产尺寸；地图不可用统一固定高裁切。
- **验收：**首次图片加载前后其后标题位置不被插入高度推动；hash定位保持目标可见；记录生产CLS作为补充。

### A11 · 窄屏缺少文章目录，侧栏标题难辨

- **分类 / 范围：**阅读效率/可访问性；Blog/Knowledge；V03/V06/V07。
- **现象与证据：**低于lg目录隐藏；Knowledge全站导航被移到正文之后；桌面192px侧栏长标题截断，Boss目录只显编号。

- **品牌影响：**低，保留两类IA。**优先级 / 工作量：P2 / 中。**
- **风险依赖：**手机sticky控件不要占过多视口；不改长期URL和正文语义。
- **验收：**手机能在不滚到文末的情况下到任一h2；左栏可区分相邻长标题；hash刷新有效。

### A12 · 阅读表格、代码、链接未共享完整排版规则

- **分类 / 范围：**一致性/可访问性；两类文章；V04/V06。
- **现象与证据：**Blog表格2px网格，Knowledge较轻；浅主题深色pre行号2.75:1；链接默认无下划线。
- **根因 / 改法：**共享prose参数与table/pre渲染能力，分别保留文章元信息；独立代码token与链接常驻线索。
- **品牌影响：**低。**优先级 / 工作量：P2 / 中。**
- **风险依赖：**MDX不同语法与长列压力样本；高亮内联颜色不能被普通全局前景误覆盖。
- **验收：**样式测试帖全部元素深浅可读；表格/代码不撑宽正文；键盘能操作滚动区和链接。

### A13 · Blog 手机筛选占据首屏

- **分类 / 范围：**信息密度/效率；Blog列表；390浅，V02。
- **现象与证据：**标签以44px触控高度多行排列，第一文章约y692；标题、搜索、排序、标签后才见内容。
- **根因 / 改法：**保留44px目标，提供当前筛选摘要和显式展开全部标签；搜索/排序作为主工具层，减少默认展开行数。
- **品牌影响：**低。**优先级 / 工作量：P2 / 小至中。**
- **风险依赖：**默认展开程度需选择；不能减少可用筛选项或使选中标签不可见。
- **验收：**默认390首屏能看到完整的首条标题和摘要起始；全部标签有直接可见的展开入口；切换排序不改外框尺寸。

### A14 · About 技能跑马灯语义与降级

- **分类 / 范围：**可访问性/主题一致性；About；V10/C。
- **现象与证据：**浅背景白色技能标签弱；两条轨全部aria-hidden，reduce只暂停且保持裁切。
- **根因 / 改法：**提供单份语义清单，重复轨作为装饰；reduce改静态换行；技能标签进入主题token。
- **品牌影响：**默认模式保留跑马灯，低。**优先级 / 工作量：P2 / 小至中。**
- **风险依赖：**与A01的固有宽度修复一起验，避免修尺寸后仍隐藏技能。
- **验收：**屏幕阅读器能读到每个技能一次；reduce模式所有技能可见，无自动运动。

### A15 · 全站键盘语义与焦点补齐

- **分类 / 范围：**可访问性；Navbar、根布局、筛选、BackToTop；V11/V14/C。
- **现象与证据：**中文站lang=en；阅读嵌套main；下拉以hover驱动；隐藏回顶按钮仍在AX；选中导航/标签缺少对应语义。
- **根因 / 改法：**中文lang、单一main、导航链接与展开控件分责、当前页状态、隐藏控件退出Tab序列、恢复滚动时同步可见状态。
- **品牌影响：**无。**优先级 / 工作量：P1 / 中。**
- **风险依赖：**键盘顺序、读屏与SPA路由公告；不能把所有按钮改成同一种ARIA角色。
- **验收：**只用键盘能打开所有子入口、筛选、搜索和回顶，无不可见焦点；页面地标与当前项可读。

### A16 · reduced-motion 覆盖不完整

- **分类 / 范围：**可访问性；Hero、Dashboard、词云、搜索、PageTransition、BackToTop；C。
- **现象与证据：**Backdrop有hook、marquee有暂停CSS，但其他运动未统一处理；本轮reduce=true不可模拟。
- **根因 / 改法：**建立共享运动偏好策略，按第6.5节分别降级，保留内容与反馈。
- **品牌影响：**只影响用户偏好模式，低。**优先级 / 工作量：P1 / 中。**
- **风险依赖：**必须在支持系统设置或媒体模拟的环境补实测；不要把style=0秒当完整可用性验收。
- **验收：**reduce=true下无连续运动/空间飞入，导航搜索照常可用，目录滚动和技能清单自然可用。

### A17 · 404 与空结果缺少稳定承托

- **分类 / 范围：**一致性/可访问性；404、Blog空结果；1440深/浅、390浅，V02/V12。
- **现象与证据：**说明直接压在高频明亮背景上，手机浅色404灰字难辨；404仍是英文开发语境文案。
- **根因 / 改法：**用轻量状态容器和中文说明、返回/搜索路径；空结果保留筛选上下文与清除入口，不必复刻完整阅读卡片。
- **品牌影响：**低，保留人物背景。**优先级 / 工作量：P2 / 小。**
- **风险依赖：**错误状态本轮未注入，只能将其作为同族规划。
- **验收：**404/空/错误/加载各有可辨状态和恢复动作，手机深浅文字可读，不暴露原始技术错误给普通读者。

### A18 · Footer、主题入口与页面族边距

- **分类 / 范围：**一致性/操作效率；Footer和页面壳；V08–V14。

- **品牌影响：**低。**优先级 / 工作量：P2 / 小至中。**
- **风险依赖：**Navbar拥挤程度与手机菜单设计；Footer底部对齐的现有flex机制保留。
- **验收：**长文顶部或阅读中可切主题；列表/导航/Footer边轨有明确关系；切换主题不改变按钮尺寸。

### A19 · 列表状态和阅读历史的承接需扩大验证

- **分类 / 范围：**交互一致性风险；Blog筛选、知识分类、历史恢复；C/V05/V09。
- **现象与证据：**Knowledge分类进入URL；Blog查询/标签/排序主要是本地state。项目后退前进成功，但没有证明所有列表状态均可恢复。
- **根因 / 改法：**定义返回列表应保留哪些状态；必要时用版本文档支持的URL/History方式保存可分享筛选，输入逐字更新可replace避免历史污染。
- **品牌影响：**无。**优先级 / 工作量：P2 / 中。**
- **风险依赖：**与现有query参数、静态路径、搜索索引无冲突；不能引入服务端状态依赖。
- **验收：**筛选→文章→后退恢复筛选/排序/合理滚动；刷新URL语义一致；hash恢复不被回顶逻辑覆盖。

### A20 · 静态预览导航异常需独立复核

- **分类 / 范围：**客观观察，归因未定；最初3000静态预览，V03前置记录。
- **现象与证据：**文章客户端跳转后内容空白，刷新恢复；3002当前开发站不复现。
- **可能根因 / 改法：**检查构建与当前提交对应关系、静态RSC/HTML请求响应和预览服务器回退行为；在已知新构建上重测，不能先改UI。
- **品牌影响：**无。**优先级 / 工作量：P2调查；若正式产物复现升P1 / 中。**
- **风险依赖：**本轮仅文档，不重新生成静态产物；不能把此项视作已修复。
- **验收：**同一已知构建下静态深层点击/刷新/后退均显示正文，404正确，资源路径完整。

### A21 · Studio：与公开页面分开评价

- **分类 / 范围：**本地工具可用性/主题一致性；`/studio/dashboard/`；1440/768/390浅，V13。
- **现象与证据：**开发环境有效，选择Knowledge与缩窄/恢复默认成功；手机仍缩放12列画布且控制区在长画布之后，文字较小。背景沿用home且缺少阅读承托，黑色说明压在图片上。
- **根因 / 改法：**工具可采用更实的主题表面；手机把选中项与尺寸控制放在画布附近，保留非拖拽路径；增加选中/结果状态语义。
- **品牌影响：**公开站无影响。**优先级 / 工作量：P3 / 中。**
- **风险依赖：**明确仅开发工具，不扩大成账号后台；原生拖拽、复制/下载故障处理另验。
- **验收：**触控或键盘可选择/移动/缩放并获知结果；手机不需要反复滚整页；生产环境按现有设计不可访问。

### A22 · 目录末段高亮边界

- **分类 / 范围：**阅读定位风险；Blog目录；1440深，V03。
- **现象与证据：**点击“结论”后已接近文末、进度100%，采样时目录仍高亮“解决方式”；C：目录以固定上方激活线判断，末段不一定能滚到该线。
- **根因 / 改法：**在保留自然滚动的前提下定义文末激活规则，并检查hash点击与滚动观察的交接，不增加页面尾部空白强行凑位置。
- **品牌影响：**无。**优先级 / 工作量：P2 / 小。**
- **风险依赖：**需在内容尺寸稳定后重复确认；字体/图片加载可能改变章节位置。
- **验收：**文末与短最后章节可正确高亮；点击目录后不被旧观察结果立即覆盖。

## 13. 分阶段优化路线

### Quick Wins：低风险、收益明显

先完成A01尺寸传播链定位与修复、A05状态色/强调白字、A07Hero入口偏移与命名、A15语言/隐藏焦点问题。搜索A03属于高收益必要修复，可单独一轮，避免和整站动画同时改。每个修复用本文样本截图与几何值回归，不在此阶段换背景或布局风格。

退出条件：手机三类溢出消失；核心搜索键盘闭环；标签可读；排序稳定性与Hero未受损。

### System Unification：主题、排版、间距和共享组件

将现有content-card成果扩展为语义色、表面、边轨、焦点、控件和状态系统。处理A06首页浅色、A17状态页、A18Footer/主题入口；明确各页面族宽度。只合并样式责任，不把Blog日期和Knowledge版本状态合成同一元数据模型。

退出条件：深浅主题表达同一品牌；组件不再各自硬编码语义色；列表族和阅读族各有稳定基线；视觉特例有命名和理由。

### Motion Pass：路由切换与内部动效

按第6节先验证路由退出可行性，再统一页面进入、内部stagger和微交互；处理A02菜单流、A08路由、A09合成、A16减弱动画和A19历史承接。一次只选一个过渡方向验证，不能同时改图、字体和布局导致无法归因。

退出条件：有真实退出/进入证据或明确未完成项；快速导航无过期背景；前进后退和hash语义正确；reduce=true实测通过。生产静态导航A20必须在发布前独立补验。

### Reading Pass：Blog 与 Knowledge 阅读体验

处理A10图片尺寸、A11移动目录/长标题、A12表格代码链接、A22目录末段，以及阅读玻璃承托。以MDX样式帖、Experience修复、46个Boss长教程为不同压力样本。保留正文语义、图片和稳定URL，禁止为了整齐裁掉信息。

退出条件：连续阅读时对比、行宽、段距稳定；表格代码局部滚动；加载图片不推动已定位章节；手机能够快速定位与切主题。

### Optional Exploration：需要用户选择的审美方向

| 选择题 | 选项与取舍 | 建议如何选择 |
| --- | --- | --- |

### 14.2 性能与风险验证
