# 1.x UI 刷新记录

> 本文记录 UI 条目的设计判断与验收，不替代 `docs/roadmap-1.x.md` 的工作清单。

## 范围

- 保留首页 Hero 的插画背景和个人表达；不在本轮重做首页 Dashboard。
- 首页、Knowledge、Blog、Projects、About 各自使用一张背景图；背景随板块切换而变化。
- 修正内容页标题、摘要和入口链接对固定白字的依赖。
- 手机端不再在页头挤入全部文字导航；以菜单面板承载完整导航。

## 视觉取舍

背景图为经过 2K 上限压缩的 WebP；首页与 About 保留原图观感，Knowledge、Blog、Projects 通过随主题变化的可读性蒙版保证正文对比度。背景切换只让新图短距离进入，避免多图轨道和透明度淡入造成的干扰。

正文标题使用 `text-fg`，摘要使用 `text-fg/65`。卡片继续使用既有 `surface`、边框和玻璃材质，避免建立第二套设计语言。

## 响应式导航

桌面（`md` 及以上）继续使用现有的胶囊导航和条目下拉菜单。手机端仅显示 Avatar、菜单和搜索三个不小于 44px 的入口；展开后以带明确关闭操作的面板显示一级与二级导航。这样避免文字逐字换行，并保留直接到分类页的路径。

## 验收

- 在 390px、768px、1024px、1440px 检查导航无横向溢出，所有入口可点击且焦点可见。
- 检查每个板块的背景图、过渡方向和明暗主题下的文本对比度。
- 在明暗主题下检查标题、摘要、卡片、菜单与链接的对比度。
- 对静态导出的 `out/` 检查首页、内容列表、深层文章、主题切换和浏览器控制台。

## 本轮验收结果

- `npm run build` 通过，生成 26 个静态页面。
- 已在静态服务器中检查 Knowledge、Blog、Projects 的桌面页面，以及 Knowledge 的 390px 手机页面、菜单展开和明暗主题。
- 已检查页面控制台；本轮页面没有 error 或 warning。
- `npm run lint` 仍有既有的 25 errors、5 warnings；本轮相关文件单独 lint 为 0 errors、2 个既有 `<img>` warnings。

## 背景面板过渡实验

本实验位于分支 `feat/panel-background-transitions`，用于替换过于单调的内容页渐变背景。

- 资源位置：`public/images/bg/bg1.webp` 至 `bg5.webp`，依次为首页、知识库、Blog、Projects、About；仅放入已确认可公开的图片。
- 背景发布资源为 `public/images/bg/bg1.webp` 至 `bg5.webp`；它们直接进入 Git 和静态部署产物，原始大图仅保留在本地背景素材目录。
- 背景源文件放入 `assets/images-source/bg/` 后，`optimize-static-assets.mjs` 会输出同名 WebP；背景的最长边限制为 2048px，以 `inside` 模式保持原始宽高比，绝不强制拉伸。图片加载失败时回退为主题纯色，不再保留旧背景图。
- 主导航顺序定义为“首页 → 知识库 → Blog → Projects → About”。切换时只使用起点与终点两张图：旧图固定铺满底层，新图从对应方向约 6% 的短距离滑到自己的中心构图。跨页不会再刷过中间背景。文章详情沿用所属板块背景。
- 所有背景以 1.08 倍显示，给短距离平移留出安全余量，不会露出黑色底层。过渡仅使用背景位移的缓出曲线，不改变背景透明度；除首页和 About 外的可读性遮罩随主题切换：浅色主题为白色亮化层，深色主题为暗化层。`prefers-reduced-motion` 下直接切换背景。
- 连续导航时，未完成的入场图会立刻被最新目标图替换；过时动画的完成回调会被忽略，因此不会留下旧状态或累积多个过渡。
- 首页与 About 的背景会随文档滚动从 `blur(0px)` 渐变至 `blur(12px)`；使用 Framer Motion 的滚动值直接写入图片样式，不通过滚轮事件触发 React 重渲染。减少动态效果偏好下保持清晰静态背景。
- 切回首页或 About 时，背景先清除离开页面时的滚动模糊进度，再于两帧后按最终 `scrollY` 同步；因此页面已回到顶部时不会保留此前底部的模糊，浏览器恢复非零滚动位置时也能正确匹配。
- Blog 卡片入场仅在外层执行短距离位移，带 `backdrop-blur` 的卡片本身始终静态、立即渲染；避开透明度动画与模糊卡片叠加时的合成掉帧。
- Blog 列表改为单列文章流：左侧日期、右侧标题与两行摘要，保留玻璃卡片边界与标签交互；以阅读顺序区分于 Knowledge 的分类／状态资料列表，避免多列卡片因内容长度形成不齐的网格。
- Projects 保留卡片网格：本站项目在平板及以上独占一行作为精选项，其余项目两列排列；项目卡明确显示“查看项目”入口，手机端取消固定最小高度以避免无意义留白。
